# Усогласеност со трудот

Овој документ ги поврзува тврдењата од трудот *Automated Company Ranking and Segmentation via Open Data Registries* со имплементацијата. Статусот е искрен: **Имплементирано**, **Делумно** или **Планирано** (како што и трудот ги означува идните работи).

## Тек (pipeline)

| Тврдење во трудот | Статус | Каде во кодот / како да се провери |
|---|---|---|
| Скрејпинг по сектори од zk.mk, пагинација, 10 сектори | Имплементирано | `CompanyScraperService`, `ScrapeSectorJob`, `SectorEnum`. Команда `app:scrape-companies-command [--sync] [--sector=...]` |
| Скрејпинг и од CompanyWall | Не е имплементирано | Се скрејпа само zk.mk |
| Асинхрона обработка преку queue | Имплементирано | Една `ScrapeSectorJob` по сектор во batch (`ScrapeDispatcher`); потребен е `php artisan queue:work` |
| Пауза ~0,3 с и timeouts 5–15 с | Имплементирано | `config/scraping.php` (`SCRAPER_DELAY_MS`, `SCRAPER_TIMEOUT`). `zk.mk/robots.txt` бара `Crawl-delay: 5`, па секој run логира предупредување кога паузата е пократка |
| Почитување на robots.txt | Делумно | `Disallow` правилата се проверуваат (`RobotsTxt`); `Crawl-delay` е конфигурабилен, не е наметнат |
| Нормализација на имиња (суфикси, мали букви, специјални знаци, транслитерација) | Имплементирано | `App\Support\CompanyNameNormalizer`; `companies.normalized_name` |
| Спречување дупликати (`updateOrCreate` + нормализација) | Имплементирано | Скрејперот бара по `normalized_name`; `app:deduplicate-companies [--dry-run]` ги спојува постојните |
| Извлекување име, сектор, град, адреса, телефон, е-пошта | Делумно | Е-пошта не е достапна на листите на zk.mk (при мерење: 0 од 155 записи) |
| Збогатување со е-пошта: сајт, пребарување, шаблон | Имплементирано | `Services/EmailEnrichment/Strategies/*` |
| Генерираните адреси се означени како *inferred* | Имплементирано | `companies.email_source` (`EmailSource`); беџ и филтер во листата; `app:backfill-email-source` |
| Валидација на е-пошта (`filter_var`, .mk приоритет) | Имплементирано | `EmailExtractor` (плус блок-листа за tracker/placeholder адреси, `app:clean-junk-emails`) |
| SMTP-верификација на е-пошти | Планирано | Трудот го наведува како идна работа |

## Индекс на активност

`activity_index = 0,5·E + 0,3·P + 0,2·F` — `ActivityIndexCalculator`, `config/activity_index.php`.

| Компонента | Дефиниција во имплементацијата |
|---|---|
| E | Бинарно: има употреблива е-пошта (претпоставените се бројат по подразбирање; `ACTIVITY_INFERRED_EMAIL_COUNTS=false` ги исклучува) |
| P | Број на јавни извори (регистар, веб-сајт, пребарување) / 3 |
| F | `scrape_count`, min–max нормализирано на логаритамска скала, во [0, 1]; 0 ако нема варијација |

Сите компоненти се во [0, 1]. Индексот е хевристика, не предиктивен модел.

## ВИ

| Тврдење | Статус | Забелешка |
|---|---|---|
| Генерирање понуда според сектор, активност и контекст | Имплементирано | `OfferAgent` + `OfferPromptBuilder` (сектор, град, ниво на активност). „Историја на ангажман“ не се користи |
| Препораки за целни компании | Имплементирано | `RecommendationAgent`; кандидати: топ 50 по индекс за сектор и по избор град, без означени дупликати/неактивни |
| Откривање дупликати/неактивни/неконзистентни записи | Имплементирано | `ValidationAgent`, `app:detect-invalid-companies`. Записите се **означуваат**, не се бришат автоматски; рачно отстранување преку „Квалитет на податоци“ во листата |
| Сегментација | Делумно | По правила (сектор, град, индекс), без автоматско ВИ-групирање — како што трудот и наведува |

## Понуди и испраќање

| Тврдење | Статус | Каде |
|---|---|---|
| Статуси `pending`, `sent`, `failed`, `opened` со времиња и грешки | Имплементирано | `sent_offers`, `SendOfferService`, релацијата „Испраќања“ на понудата |
| Иста понуда не се испраќа двапати до иста компанија | Имплементирано | `unique(offer_id, company_id)` + прескокнување на веќе испратени |
| Претпоставените е-пошти не се користат стандардно | Имплементирано | Опција „Вклучи претпоставени“ при испраќање |
| Испраќање преку Mailgun/SendGrid | Планирано | Сега Laravel Mail; со `MAIL_MAILER=log` пораките се запишуваат во `storage/logs/laravel.log` (**тест-режим**, нема вистинска достава) |
| `opened` | Делумно | Преку tracking pixel; индикативно (клиенти што блокираат слики) |
| Закажување на испраќање | Не е имплементирано | |

## Контролна табла и корисничко ниво

| Тврдење | Статус |
|---|---|
| Административен панел на македонски (Filament 4) | Имплементирано |
| Статистика по сектор, понуди и статуси, филтри, пребарување, сортирање по индекс | Имплементирано |
| Автентикација и улоги | Делумно — најава постои; сите корисници се администратори |

| Vue.js 3 / Inertia SPA frontend | Планирано (трудот: „во развој“) |

## Табела II (метрики)

Командата `app:company-statistics [--csv=файл]` ги пресметува сите метрики од базата (`StatisticsService`):

| Метрика | Како се пресметува |
|---|---|
| Вкупно компании, тестирани сектори | `COUNT(*)`, `COUNT(DISTINCT sector)` |
| Почетна покриеност со е-пошта | Компании чија е-пошта е земена директно од регистарот / вкупно |
| Покриеност по збогатување | Компании со е-пошта / вкупно; се прикажува и колку од нив се претпоставени |
| Намалување на дупликатите | Листинзи што повторуваат веќе виден запис во истиот run / вкупно видени листинзи (`scrape_runs`) |
| Просечно време по сектор | Просек на `duration_seconds` на завршени runs |

> Бројките објавени во трудот (5.967 компании, 5,5% → 19,79%, 5,21%, 3,2 мин.) се од снимка на базата во времето на пишувањето. Тековната база и мерењата со овие команди може да се разликуваат, па секоја нова бројка треба да се наведе со датум и командата со која е добиена.
