# Усогласеност со трудот

Овој документ ги поврзува тврдењата од трудот *Automated Company Ranking and Segmentation via Open Data Registries* со имплементацијата. Статусот е искрен: **Имплементирано**, **Делумно** или **Планирано** (како што и трудот ги означува идните работи).

Принцип: **ништо не се претпоставува**. Податоците доаѓаат од скрејпинг на јавни страници; адреси генерирани по шаблон (`info@домен`) се исклучени по подразбирање и, ако се вклучат, се означуваат како *inferred* и се чуваат само ако доменот прима пошта (MX).

## Тек (pipeline)

Преглед и копчиња за секоја фаза: **Пајплајн** во административниот панел. Сите фази работат преку queue (`php artisan queue:work`).

| # | Фаза | Извор | Команда |
|---|---|---|---|
| 1 | Собирање | zk.mk листи по сектор | `app:scrape-companies-command [--sync] [--sector=]` |
| 2 | Чистење | нормализација на имиња, спојување | `app:deduplicate-companies [--dry-run]` |
| 3 | Профили | zk.mk профил на компанија: **веб-сајт**, Facebook, Instagram, дејности | `app:scrape-company-profiles [--limit=]` |
| 4 | Регистарски податоци | CompanyWall: ЕДБ, ЕМБС, датум на основање, големина, вработени | `app:scrape-companywall [--limit=]` |
| 5 | Е-пошти | веб-сајтот од профилот (почетна + контакт-страници); за компании без сајт — пребарување чиј домен го содржи името | `app:run-email-enrichment [--limit=]` |
| 6 | Индекс | `0,5·E + 0,3·P + 0,2·F` | `app:calculate-activity-index` |
| 7 | Понуди | ВИ + идемпотентно испраќање | панел → Понуди |

## Тврдења од трудот

| Тврдење во трудот | Статус | Каде во кодот / забелешка |
|---|---|---|
| Скрејпинг по сектори од zk.mk, пагинација, 10 сектори | Имплементирано | `CompanyScraperService`, `ScrapeSectorJob`, `SectorEnum` |
| Скрејпинг и од CompanyWall | Имплементирано | `CompanyWallScraper`. Профил се прифаќа само ако името (и градот) се совпаѓаат. CompanyWall не објавува е-пошта ниту веб-сајт, па служи за ЕДБ/ЕМБС/големина и како втор извор за P |
| Асинхрона обработка преку queue | Имплементирано | Batch од jobs; `ScrapeSectorJob`, `ProcessCompaniesJob` |
| Пауза ~0,3 с и timeouts 5–15 с | Имплементирано | `config/scraping.php`. `zk.mk/robots.txt` бара `Crawl-delay: 5`; секој run логира предупредување кога паузата е пократка, `SCRAPER_DELAY_MS=5000` целосно го почитува |
| Почитување на robots.txt | Делумно | `Disallow` правилата се проверуваат (`RobotsTxt`); `Crawl-delay` е конфигурабилен, не е наметнат |
| Нормализација на имиња | Имплементирано | `CompanyNameNormalizer`; `companies.normalized_name` |
| Спречување дупликати | Имплементирано | Скрејперот бара по `normalized_name`; `app:deduplicate-companies` ги спојува постојните |
| Извлекување име, сектор, град, адреса, телефон, веб-сајт | Имплементирано | Веб-сајтот и социјалните мрежи се од профилот на zk.mk |
| Е-пошта од регистарот | Не е достапна | zk.mk ја крие е-поштата зад најава; затоа почетната покриеност од регистарот е 0% |
| Збогатување со е-пошта: сајт, пребарување, шаблон | Имплементирано | `Strategies/*`. Шаблонот (`info@…`) е исклучен по подразбирање (`ENRICHMENT_INFERRED_ENABLED`) |
| Генерираните адреси се означени како *inferred* | Имплементирано | `companies.email_source`; беџ и филтер во листата |
| Валидација на е-пошта | Имплементирано | `filter_var`, блок-листа за tracker/паркирани домени, `.mk` приоритет, MX проверка на доменот (`email_domain_has_mx`, `app:verify-email-domains`) |
| SMTP-верификација на сандаче | Планирано | Трудот го наведува како идна работа |

## Индекс на активност

`activity_index = 0,5·E + 0,3·P + 0,2·F` — `ActivityIndexCalculator`, `config/activity_index.php`. Компонентите се во [0, 1].

| Компонента | Дефиниција |
|---|---|
| E | Бинарно: има употреблива е-пошта што е **пронајдена** (претпоставените не се бројат; `ACTIVITY_INFERRED_EMAIL_COUNTS=true` ги вклучува) |
| P | Присуство во јавни извори: zk.mk (секогаш) + сопствен веб-сајт + CompanyWall, поделено со 3 |
| F | `scrape_count` (колку пати е видена компанијата во листинзи), min–max на логаритамска скала; 0 ако нема варијација |

Индексот е хевристика, не предиктивен модел. На страницата на компанијата се гледаат E, P и F посебно.

## ВИ

| Тврдење | Статус | Забелешка |
|---|---|---|
| Генерирање понуда според сектор, активност и контекст | Имплементирано | `OfferAgent` + `OfferPromptBuilder` (сектор, град, ниво на активност); на македонски |
| Препораки за целни компании | Имплементирано | `RecommendationAgent`; кандидати: топ 50 по индекс за сектор и по избор град, без означени дупликати/неактивни |
| Откривање дупликати/неактивни/неконзистентни записи | Имплементирано | `ValidationAgent`, `app:detect-invalid-companies`; записите се **означуваат**, не се бришат автоматски |
| Сегментација | Делумно | По правила (сектор, град, индекс), без автоматско ВИ-групирање — како што трудот и наведува |

## Понуди и испраќање

| Тврдење | Статус | Каде |
|---|---|---|
| Статуси `pending`, `sent`, `failed`, `opened` со времиња и грешки | Имплементирано | `sent_offers`, `SendOfferService` |
| Иста понуда не се испраќа двапати до иста компанија | Имплементирано | `unique(offer_id, company_id)` + прескокнување |
| Претпоставените е-пошти не се користат стандардно | Имплементирано | Опција „Вклучи претпоставени“ |
| Испраќање преку Mailgun/SendGrid | Планирано | Сега Laravel Mail; `MAIL_MAILER=log` пишува во `storage/logs/laravel.log` (**тест-режим**) |
| `opened` | Делумно | Tracking pixel; индикативно |
| Закажување на испраќање | Имплементирано | „Закажи испраќање“ на понудата; `app:send-scheduled-offers` (scheduler, секоја минута); еднократно по понуда |

## Контролна табла и корисничко ниво

| Тврдење | Статус |

## Табела II (метрики)

`app:company-statistics [--csv=файл]` ги пресметува сите метрики од базата (`StatisticsService`):

| Метрика | Како се пресметува |
|---|---|
| Вкупно компании, тестирани сектори | `COUNT(*)`, `COUNT(DISTINCT sector)` |
| Почетна покриеност со е-пошта | Компании чија е-пошта е земена директно од регистарот / вкупно |
| Покриеност по збогатување | Компании со е-пошта / вкупно; се прикажува и колку од нив се претпоставени |
| Намалување на дупликатите | Листинзи што повторуваат веќе виден запис во истиот run / вкупно видени листинзи (`scrape_runs`) |
| Просечно време по сектор | Просек на `duration_seconds` на завршени runs |

> Бројките објавени во трудот (5.967 компании, 5,5% → 19,79%, 5,21%, 3,2 мин.) се од снимка на базата во времето на пишувањето. Тековните мерења (18.10.2026) се во `docs/MEASUREMENTS.md` и може да се разликуваат; секоја нова бројка се наведува со датум и командата со која е добиена.
